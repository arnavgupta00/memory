## Failure modes if agent searches wrong
- **Only anchoring on "Run for the Cure"** then stopping → undercount; other participations never enter the bag.
- **BM25 on generic "charity" only** → often misses Walk for Wildlife (notes emphasize volunteer/wildlife, not the word charity).
- **Querying future/planned events** ("charity swim", "cycling event next month") from the anchor session → distractors that are not completed participations.
- **Dropping post-anchor events** (Bike-a-Thon in November) → cannot safely order "before Oct 15"; risk of wrong count if dates are fuzzy.
- **Adding from non-last hits / inventing IDs** → invalid under tool contract; bag may miss golds that only appear after reformulation.
- **Done after 1–2 sessions** → temporal count question needs the full dated event set, not just the named event.

## Reusable rules (3–7 bullets, generalist wording — no qid names)
- For "before/after \<named event\>" questions, **grep the proper noun first** to bag the anchor, then broaden to the event class.
- After the class BM25 hop, **grep alternate role labels** (volunteer, walk, gala, tournament, marathon) and named titles when notes omit the class word.
- **Add sessions as soon as they appear** in the last hits; do not wait until the final hop to bag known candidates.
- For count/temporal questions, bag **dated siblings on both sides of the cutoff** so ordering can include and exclude correctly.
- Prefer **entity + event-type queries** (`"… tournament"`, `"… gala"`) over vague motivation phrases ("stay motivated", "local events").
- If a hop returns mostly plans/future interest, **reformulate toward completed-participation cues** (participated, volunteered, attended, raised) before calling done.
- Stop with `done` only when the bag covers the **anchor plus every aspect needed for the comparison/count**, not when the first relevant session appears.
