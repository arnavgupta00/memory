# Architecture 0004 checkpoint — 2026-07-26

## Checkpoint decision

Architecture 0004 is frozen with the **simple answer prompt** as the canonical
answerer. Retrieval stays the W2/S1/K48/80k BM25 turn-window backbone. Further
prompt or retrieval work starts from this measured baseline rather than from the
original over-abstaining `answer.yaml`.

## Fixed experiment

- Architecture: `0004-session-retrieval-backbone`
- Retrieval: BM25 turn windows, `window_turns=2`, `window_stride=1`, `top_k=48`,
  `char_budget=80000`, `max_turn_chars=4000`, `temporal_boost=0.15`
- Answer prompt: `prompts/answer-v2-simple.yaml` (default `options.answer_prompt`)
- Answer model: `gpt-5.4-nano-2026-03-17`
- Canonical judge: `gpt-4o-2024-08-06`, temperature `0`
- Canonical config: `configs/architecture-0004-canary2-simple.yaml`
- Write-time model calls: none
- Answer-time model calls: one per question

## Measured results

| Evidence | Result |
|---|---:|
| Offline recall (W2/S1/K48/80k) | session hit 99.4%; answer-turn complete 87.0% |
| canary-2 + original `answer.yaml` | 27/60 (45.0%) |
| Oracle-context control on those 33 wrongs | 5/33 — prompt bottleneck, not haystack |
| `dev-60-v1` A/B: baseline / simple / rules | 36.7% / **56.7%** / 46.7% |
| canary-2 + `answer-v2-simple` (confirmation) | **35/60 (58.3%)**; abstention 9/10 |

Preference remains weak (2/10 on canary-2). Development sets `dev-9-v1` and
`dev-60-v1` are contaminated by design and are not blind results.
