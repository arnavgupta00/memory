## Failure modes if agent searches wrong

- **Visit-only query:** Searching solely on "music store this weekend" or "guitar shopping tips" misses gold because indexed notes never use store/visit wording.
- **Generic guitar advice:** Broad queries like "how to buy a guitar" or "guitar tips" dilute hits across unrelated sessions and may omit the upgrade-preference session.
- **Assistant-echo queries:** Querying advice the assistant gave (genres, tuning how-tos) instead of user-stated upgrade intent and model names.
- **Stale reformulation:** After a weak Hop 1, repeating the same visit phrasing instead of pivoting to **Fender / Gibson / Les Paul / Stratocaster / upgrade**.
- **add_sessions violation:** Pulling IDs from an earlier hop after a later empty search, or adding sessions not present in the **last** hit list.
- **Premature done:** Stopping on a generic guitar session without the Strat→Les Paul preference context needed for personalization.

## Reusable rules

- For preference questions, run a **question-shaped bm25** first, then **reformulate with entities and objects** the user actually owns or is considering (brands, models, upgrade verbs)—not only the new ask's surface words.
- When the question introduces **new situational framing** (e.g., "this weekend", "music store") absent from notes, **grep or bm25 on durable nouns** from the domain (instrument models, product names) to recover prior context.
- Use **grep_notes on 2–5 proper nouns or distinctive compound phrases** (model names, tuning names, feature terms) when lexical notes are rich but the first query's vocabulary mismatches indexed keyphrases.
- **add_sessions only from the immediately preceding search's hit list**; with one clear gold hit, add that session before done rather than expanding the bag speculatively.
- Before **done**, confirm the bag contains a session whose **facts state user preferences or constraints** relevant to the question aspect—not merely topical overlap on "guitar."
- Prefer **user-turn / facts vocabulary** (upgrade, considering, differences between X and Y) over paraphrases of the assistant's explanatory content when crafting hop queries.
- If the first hop returns many guitar-adjacent but non-preference sessions, **narrow with model-pair or feature-specific terms** instead of increasing top_k alone.
