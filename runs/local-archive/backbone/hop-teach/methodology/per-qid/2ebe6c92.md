## Failure modes if agent searches wrong
- Querying only `book recommendations` / `historical fiction` floods recommendation sessions and buries the finish event.
- Searching concurrent titles (`Song of Achilles`, `Star-Touched Queen`, `Poppy War`) without a finish cue can promote in-progress or already-read books as the answer.
- Stopping after the start session (`started reading The Nightingale`) without a finish-bearing session fails the “finished … ago” aspect.
- Ignoring session_date vs question_date: a finish marked `(today)` only answers “a week ago” when that session’s date is ~7 days before the question.
- Calling `done` before `add_sessions`, or adding IDs not in the last search hits, breaks the hop contract.

## Reusable rules (3–7 bullets, generalist wording — no qid names)
- For “what did I finish / complete N days|weeks ago” questions, first hop with finish/completion verbs plus the activity object (book, course, project), not genre or recommendation language.
- After a concrete entity (title, product, place) appears in finish-bearing hits, grep that proper noun (optionally with the finish verb) to collect start/progress sibling sessions for the same entity.
- Always `add_sessions` for the finish-event session before `done`; if the bag only has start/in-progress notes, keep hopping.
- Align candidate event dates to the question’s relative time (“a week ago”, “yesterday”) using `[session_date]` plus event date hints like `(today)`, not title popularity.
- If the first BM25 pass returns only preference/recommendation chatter, reformulate toward explicit completion phrases (`finished`, `just finished`, `completed`) before expanding top_k.
- Do not treat “currently reading” / “halfway through” / “hoping to finish” notes as satisfaction of a past-finish question aspect.
