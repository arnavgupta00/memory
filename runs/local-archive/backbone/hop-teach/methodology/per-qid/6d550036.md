# Hop methodology

## Question gist

Count how many projects the user has led or is currently leading. Evidence is scattered across sessions: explicit team leadership, a solo class project, owned research presented as a poster, and a case-competition workstream. A complete bag must cover those ownership facets, not merely hits that mention “project.”

## Correct hop path

Budget: **H ≤ 4** (fits under H≤6). Selective adds only; bag max 12.

1. **Hop 1 — `grep_notes`**  
   `patterns=["led the", "I led", "solo project"]`  
   - Expect `_1` (led the data analysis team) and `_2` (solo project).  
   - **`add_sessions`**: only those two (or any other hit that clearly states first-person project ownership). Do **not** fill the bag with every “project” lexical hit.

2. **Hop 2 — `grep_notes`**  
   `patterns=["presented a poster", "my research", "case competition"]`  
   - Expect `_3` (poster / research) and `_4` (case competition).  
   - **`add_sessions`**: `_3`, `_4`.

3. **Hop 3 — optional confirm (BM25)**  
   If either facet is still missing after grep:  
   - Missing research: `bm25_notes(query="research poster academic conference consumer", top_k=10)`  
   - Missing competition: `bm25_notes(query="case competition consulting dashboard presentation", top_k=10)`  
   Add only the missing gold-relevant hits.

4. **`done`**  
   Reason: bag covers (a) explicit led-team project, (b) solo class project, (c) owned research/poster, (d) case-competition workstream — enough to enumerate led/leading projects.

**Why this beats question-paraphrase BM25:** repeating “projects led currently leading” ranks distractors that share `project`/`led`/`lead` stems and never surfaces poster/research or case-competition notes that omit those tokens.

## Failure modes

1. **Question echo BM25** — Queries built from the question text (`projects led leading leadership count`) surface weak “project” matches and a top distractor with `led`/`lead` stemming, while missing research and case-competition gold.
2. **Early bag pollution** — Adding all top-k “project” hits consumes capacity and encourages stop/done before facet coverage.
3. **Leadership-only tunnel** — Stopping after “led the” / “solo project” leaves out workstreams described as research, posters, or competitions.
4. **Synonym blindness** — Treating “project” as required vocabulary; gold ownership often appears as `research`, `poster`, `case competition`, `class project`, `solo project`.
5. **Retry loops** — Re-running near-identical BM25 queries within H≤6 wastes hops without changing the hit set.

## Reusable rules

- For count/list questions about “led / leading / my projects,” search **ownership evidence** (led, solo, my research, presented, competition) rather than paraphrasing the question.
- Prefer **`grep_notes` for exact first-person ownership phrases** before broad BM25 on common nouns like `project`.
- After one ownership hit, **pivot facets** (class project vs research vs competition vs team lead) instead of re-querying the same leadership bag of words.
- **Add selectively**: keep sessions that assert the user’s role; skip generic “project” mentions that do not imply leadership or ownership.
- If BM25 top hits are dominated by a single token (`project`), switch to **grep on distinctive event phrases** from the question’s likely answer types (poster, case competition, class project).
- Stop when **aspect coverage** is complete (each distinct owned workstream represented), not when hop budget or “strongest project BM25” is exhausted.

## Abstention / thin-notes note

Not an abstention case (`is_abstention: false`); notes coverage is full for all gold sessions. Failure here is retrieval strategy (question-echo BM25 + distractor adds), not missing annotations. If notes lacked ownership verbs/events, a thin-notes path would need broader event greps (`poster`, `competition`, `class project`) before concluding incompleteness.
