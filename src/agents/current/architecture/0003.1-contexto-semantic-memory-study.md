# Architecture 0003.1 — Contexto Semantic-Memory Study

## Why this revision exists

The first six-case Architecture 0003 run produced only 12 accepted Contexto batches out of 97.
The Observatory was rendering the stored data faithfully: accepted graphs themselves contained
runtime envelopes (`master_graph`, `schema_version`, and `revision`) or copied transcript shapes
(`session`, `turns`, `role`, and `content`). The dominant fault was memory construction, not graph
layout.

## Query-blind expert reconstruction

Six independent GPT-5.6 experts reconstructed an ideal graph from ordered raw sessions. During the
first phase, each expert was forbidden from seeing the benchmark question, reference answer,
prediction, judgment, existing graph, or mutation records. Only after freezing an ideal graph and
construction method did the expert inspect the benchmark target and diagnose Architecture 0003.

| Case | Task class | Old accepted batches | Query-blind memory that mattered |
|---|---|---:|---|
| `e47becba` | single-session user | 4 / 17 | user's Business Administration degree |
| `db467c8c` | knowledge update | 4 / 16 | parents' stay changed from six to nine months |
| `a11281a2` | multi-session arithmetic | 1 / 16 | Instagram measurements changed from about 250 to about 350 |
| `c8090214` | temporal reasoning | 1 / 15 | Holiday Market occurred one week before the Black Friday phone purchase |
| `71315a70` | knowledge update | 1 / 17 | sculpture effort changed from 5–6 to 10–12 hours |
| `gpt4_1e4a8aeb` | temporal reasoning | 1 / 16 | workshop and tomato planting events occurred on April 15 and April 21 |

The frozen study artifacts live in `.cache/contexto-study/<case-id>/` and are intentionally ignored
because they include large diagnostic reconstructions.

## Shared construction method

All six experts converged on the following process without seeing one another's work:

1. Audit user turns before assistant prose.
2. Extract durable personal facts, related entities, quantities, dates, durations, preferences,
   routines, possessions, health reports, events, adopted decisions, plans, and projects.
3. Exclude generic advice, public knowledge, pasted documents, fictional material, formatting or
   generation tasks, and unadopted assistant suggestions.
4. Resolve repeated entities conservatively and reuse a stable semantic path for the same facet.
5. Preserve mutable values as dated observations; the latest supported observation is current and
   earlier values remain history.
6. Keep provenance on the smallest semantic assertion. Raw sessions remain in the external archive.
7. Account for every input session as either a source of semantic memory or an explicit no-memory
   decision.

## Contract change

Contexto no longer emits RFC 6902 operations, graph replacements, JSON pointers, graph envelopes,
or complete provenance records. It emits flat typed semantic updates:

```text
domain + semantic path + memory type + update mode + value
       + optional effective time/unit + batch-local source locator
```

The deterministic reducer now owns:

- parent creation and stable storage paths;
- graph revision and provenance metadata;
- exact source date, batch ID, and evidence excerpt;
- add-versus-update behavior;
- append deduplication;
- observation history and current-state selection;
- per-update validation and partial salvage;
- denial of transcript and runtime wrapper keys;
- batch coverage validation.

The model sees only a compact semantic-memory catalog, never `MasterContextGraph`. Rejected model
proposals remain diagnostic artifacts and are excluded from the final answer context.

## Graph representation and Observatory behavior

The canonical graph remains a dynamic nested semantic tree. Its top level is restricted to meaningful
domains such as `people`, `relationships`, `health`, `possessions`, `events`, `plans`, `projects`, and
`measurements`. A terminal fact is a runtime-managed memory cell containing a current assertion and
append-only observation history.

The Observatory collapses each memory-cell envelope into one semantic leaf. It shows the domain,
entity/facet path, and current value instead of rendering `current`, `history`, provenance metadata,
or schema fields as unrelated graph nodes.

## Acceptance gates

Before another scored run, the Contexto-only six-case replay must demonstrate:

- zero runtime/transcript wrapper paths;
- every B-session batch accounted for;
- no whole-batch loss from one invalid update;
- high update acceptance with explicit reasons for every rejected update;
- current/history behavior on the two knowledge-update cases;
- recoverable event dates or relative anchors on both temporal cases;
- all prompts, validated outputs, usage, latency, request IDs, mutations, and final graphs preserved.

## Six-case generalization loop

The fixed six-case panel was rerun under new run IDs after each query-blind architecture revision.
No completed run was overwritten or resumed across a prompt change.

| Run | Canonical score | Agent cost estimate | Total agent tokens | Main result |
|---|---:|---:|---:|---|

inputs; it does not claim a provider invoice total.

## General fixes validated by the loop

- A deterministic, query-blind personal-signal index scans user turns before Contexto. Signal IDs
  are content-derived and stable under batching or ranking changes.
- Time, quantity, change, relationship, and possession/project cues are retained exactly with source
  coordinates. High-priority clauses remain in an unverified safety ledger even when Contexto omits
  them; they never become canonical graph facts automatically.
- Canonical provenance is deduplicated into a direct-evidence ledger. The final model receives a
  compact graph without repeated provenance because the ledger carries the exact excerpts and paths.
- A small deterministic lexical projection selects question-relevant excerpts from canonical
  provenance and conservatively from the unverified ledger. It uses no LLM, embeddings, benchmark
  answer, or ingestion-time question access.
- The final-answer prompt distinguishes observation/mention time from event-valid time and expresses
  temporal comparison as abstract offset algebra rather than a benchmark-shaped example.
- Resume replays only the semantic updates accepted during the original batch. Rejected update
  indices are validated, preventing a previously rejected mutation from changing the replay hash.

The final run reduced answer-role input from 356,071 tokens in V2 to 285,650 tokens while improving
the score from 5/6 to 6/6. Memory construction remains the dominant cost and retry source.

## Anti-overfit and integrity checks

- Production source and YAML prompts contain no panel IDs, target entity names, or gold-answer
  literals.
- Contexto and Shino remain query-blind. Only deterministic answer-time projection and the final
  answer model receive the question.
- All 97 Contexto, 30 Shino, and 6 answer calls expected by the cadence were present in the final
  report.
- All six event streams replay to the exact stored final-graph hash.
- Strict TypeScript, ESLint, 42 agent tests, Ruff, mypy, the complete offline Python test suite,
  frontend lint/test/build, and dataset checksum verification pass.
