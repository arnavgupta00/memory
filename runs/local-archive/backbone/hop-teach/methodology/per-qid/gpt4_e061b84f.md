## Failure modes

- **Plan vs participated**: treating “Thursday evening after volleyball” or waterfront ride plans as a fourth event; the Q wants competed-in events with completion/participation evidence.
- **Topic bleed**: keeping shoe / hydration / injury-prevention sessions that lack a named race/tournament on that day.
- **Partial bag**: retrieving triathlon + 5K but missing soccer (or vice versa) → cannot answer a three-event order.
- **Wrong sort key**: sorting by retrieval rank or by sport name instead of `session_date` / event day.
- **Title collapse**: merging “5K” training talk with Midsummer 5K, or “bike ride” with Spring Sprint Triathlon without the event name in notes.
- **Window slip**: including sports outside the past-month window relative to the question date.

## Reusable rules (generalist)

1. For “order of N events in the past month,” require N distinct **participation/completion** event notes, then sort strictly by session/event date.
2. Prefer **named event titles** in keyphrases/events over ambient sport activity (training, gear, recovery tips).
3. Treat “today” / “just finished” / “participate … today” in facts/events as stronger than future-plan language (“thinking of”, “after my … game”).
4. Use grep on distinctive proper names after a broad BM25 sweep so near-miss sport sessions do not crowd the bag.
5. Cap the bag to sessions that each contribute one required event; drop same-topic follow-ups that add no new dated competition.
6. Never answer a temporal order from a single multi-topic session when gold evidence is split across dated sessions—collect the set, then sort.
7. If fewer than N dated participation events survive the window, abstain or report incompleteness rather than inventing order from plans.
