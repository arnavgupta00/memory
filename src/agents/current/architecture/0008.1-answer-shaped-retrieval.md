# Architecture 0008.1 — answer-shaped retrieval workflow

**Status:** implemented as an experimental retrieval arm; not selected or certified

**Control:** Architecture 0008 `hybrid` remains unchanged. Use the
`answer-shaped` arm, or `beam1mCanary.ts --retrieval-arm answer-shaped`, to gate
this workflow without overwriting the certified baseline.

## Purpose

The focused retriever is good at finding one or a few direct facts, but its
one-shot facet planner often searches question wording rather than the language
likely to occur in the answer evidence. It also cannot use vocabulary discovered
in its first search to close missing contradiction sides, temporal endpoints,
timeline milestones, summary periods, or distributed list members.

Architecture 0008.1 adds a question-only gated two-agent workflow:

1. **Evidence architect — GPT-5.6 Luna low.** Produces a blank answer template,
   independent evidence slots, likely evidence phrases, and a completion rule.
   It predicts structure and language, never unverified factual values.
2. **Search controller — GPT-5.6 Luna low.** Generates question-anchor,
   answer-language, contrast, and temporal BM25 queries. After round one it
   classifies every evidence slot as covered, partial, or missing and creates
   one follow-up query round using vocabulary from retrieved excerpts.
3. **Deterministic search.** The original question and controller queries run
   over notes, USER, ASSISTANT, and combined views. Candidate fusion reserves
   representation for complementary evidence slots before filling by fused rank.
4. **Admission.** Focused questions retain V1-style maximum-12 admission, now
   supplied with the answer blueprint and sanitized coverage summary. Explicit
   timeline questions retain the existing maximum-192 broad route.

All structured model inputs and outputs, both candidate pools, the coverage
ledger, follow-up queries, and admission calls are preserved in case traces.
Opaque `memory_###` handles remain mandatory.

## Question-only routing

The experimental workflow activates only for explicit:

- timelines or chronological ordering;
- comprehensive summaries or histories;
- temporal intervals and endpoints;
- historical yes/no claims (`have`/`has`), explicit contradictions, or paired
  "have I ... and if so" evidence;
- exhaustive lists or aggregates.

Ordinary lookup, preference, bounded comparison, instruction, and update shapes
continue through the original one-shot hybrid planner. The router reads only the
question text; it receives no benchmark ability label or oracle metadata.

## Prompt contracts

- `prompts/hop-answer-blueprint-v1.yaml`
- `prompts/hop-answer-search-controller-v1.yaml`

The prompts use explicit role, goal, input, decision procedure, completeness,
query-lane, coverage, safety, and structured-output sections. They do not request
or expose private chain-of-thought. The inspectable reasoning artifacts are the
answer template, evidence slots, query purposes, coverage decisions, and stop rule.

## Five-question live smoke test

The corrected `answer-shaped` arm completed five BEAM 1M cases with zero errors
in 33.3 seconds, 128,148 tokens, 17 API calls, and an estimated $0.188 retrieval cost.
This is a wiring and directional recall test, not an end-to-end score claim.

| Question shape | Architecture 0008 comparison | 0008.1 result |
|---|---:|---:|
| Contradiction | pool/bag recall 0.50 / 0.50 | 0.50 / 0.50 |
| Event ordering, selected wide control | 0.40 / 0.40 | **0.467 / 0.467** |
| Protected preference | 1.00 / 1.00 | **1.00 / 1.00** |
| Summarization | 0.286 / 0.143 | **0.286 / 0.286** |
| Temporal | 1.00 / 1.00 | **1.00 / 1.00** |

Smoke artifacts are under `runs/answer-shaped-retrieval-smoke-20260802/`.
Promotion requires a paired retrieval and downstream gate across the complete
below-70% ability set plus the four protected abilities as regression controls.
