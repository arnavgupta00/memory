## Correct hop path (H≤6)

Tools only: `bm25_notes`, `grep_notes`, `add_sessions` (last hits only, bag ≤ 12), `done`.

1. **Anchor the window** (no tool): from question_date `2023/07/01`, “two weeks ago” ≈ `2023/06/17` (± a few days). Prefer session_date near that day over any sports mention.
2. **Hop 1 — `bm25_notes`**: query sport-event + participation lexicon, *not* relative-time filler. Example shape: `triathlon 5K run soccer tournament participated completed charity`. Avoid `two weeks ago`, bare `event`, and lone `2023`/`week` (they rank shopping/meal/social distractors).
3. **Hop 1 — `add_sessions`**: from **last hits only**, add sessions whose snippets show a named athletic event + completed/participate/today, especially any dated near mid-June. Cap bag ≤ 12.
4. **Hop 2 — `grep_notes`** (if BM25 returns only one sport cluster or the wrong week): pattern on alternate event nouns (`tournament`, `5K`, `triathlon`, `Midsummer`, `Spring Sprint`) to surface sibling sports sessions.
5. **Hop 2 — `add_sessions`**: add remaining last-hit sports-participation sessions still missing from the bag (multi-event disambiguation set).
6. **Hop 3 — date filter then `done`**: keep/emphasize the session whose `session_date` is ~2023/06/17; treat earlier June sports sessions as near-miss distractors for the relative clause. Stop when the mid-June participation event is in bag (siblings optional for contrast). Do not burn hops re-querying the same soft temporal bag.

## Failure modes

- **Relative-time BM25 pollution**: queries like `sports event … two weeks ago June 2023` match `event`/`week`/`ago`/`2023` on non-sports sessions (e.g. “three weeks ago” shopping), burying or demoting true sports notes.
- **Single-hit lock-in**: adding only the early-June triathlon (`answer_8c64ce26_2`) then re-adding the same id each hop (`rejected=…`) while never grepping for other sport event names.
- **Date guess without sport lexicon**: injecting a calendar day (`June 17` / `2023/06/17`) into BM25 without tournament/race terms still fails to surface the soccer session and can boost numeric/date noise.
- **Ignoring session_date vs “today” in notes**: treating any “completed … today” sports session as the answer without checking whether that session’s date is ~14 days before the question.
- **Exhausting H=6 on paraphrase loops**: repeating near-identical `bm25_notes` strings instead of switching to `grep_notes` for alternate event proper nouns.

## Reusable rules (generalist)

1. For “X ago” questions, compute a target calendar window from `question_date` first; use session_date as the hard filter after lexical recall.
2. Prefer BM25 terms that appear in notes as event names and participation verbs; drop question boilerplate (`weeks ago`, bare `event`) that is common across distractors.
3. When several same-domain events exist (multiple races/tournaments), bag the candidates then disambiguate by date proximity—not by which hit ranked first.
4. `add_sessions` only from the **immediate previous** search hits; never re-add an id already in bag; if rejected, change query tool/terms.
5. If one sport cluster dominates BM25, `grep_notes` for alternate event nouns before concluding the bag is complete.
6. Soft temporal tokens (`ago`, `week`, month names alone) are weak anchors; pair them with concrete activity nouns or abandon them for grep on event titles.
7. Stop once the window-matched participation session is bagged; extra hops that only reshuffle the same hit list do not improve recall.
